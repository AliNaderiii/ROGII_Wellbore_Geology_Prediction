# ⚠️ SYNTHETIC PIPELINE VERIFICATION ONLY

**Nothing in this directory is a competition result.**

Every file here was produced from a **synthetic field** generated by
`scripts/make_synthetic_field.py`, not from the ROGII Kaggle data. The Kaggle
mount was not available in the environment where the harness was built, so a
synthetic field was used to prove the pipeline executes correctly end to end.

## What these files do and do not establish

**They do establish:**

- The harness runs to completion on a realistic file layout.
- Both validation protocols are cross-fitted by well ID — verified by a spy
  test that records which wells each model was fitted on versus scored on.
- The leakage guards fire (public test wells, target columns, train-only
  markers, unaudited columns, spatial self-donation).
- Models train, predict, rank, and degrade gracefully on wells with 80%
  missing GR and on wells with no typewell.
- Runtime and memory are bounded.

**They do not establish anything about accuracy on the real data.** In
particular:

- The synthetic generator constructs `TVT = surface − Z` by definition. That
  hands `geom_projection` a near-exact algebraic relationship, which is almost
  certainly why it ranks first here. It will not enjoy that advantage on real
  data.
- The synthetic GR log is interpolated directly from the typewell, so the
  correlation problem is cleaner than a real tool response with bed-boundary
  effects, invasion and bad-hole intervals.
- Only 40 wells were generated, versus 773 real train wells.

**Do not quote any number in this directory as a validation result.**

## Why the in-sample diagnostic is included

`baseline_report.md` §3b reports a deliberately invalid protocol,
`INVALID_in_sample`, which fits and scores on the same wells. It is there to
quantify the exact bug that prompted this rework:

| model | in-sample RMSE | honest unseen-well RMSE | optimism |
|---|---|---|---|
| lightgbm | 0.084 | 2.493 | **~30×** |
| ridge | 1.193 | 2.016 | ~1.7× |
| hold_last | 4.538 | 4.538 | 1.0× |

A high-capacity model memorises individual well trajectories, so its in-sample
score is arbitrarily good and says nothing about unseen-well performance. Note
that the parameter-free baselines show an optimism factor of exactly 1.0 —
there is nothing for them to memorise, which is a useful internal consistency
check on the diagnostic itself.

These figures are synthetic; the *ratio* is the point, not the magnitude.

## Reproducing

```bash
python scripts/make_synthetic_field.py --n-train 40 --seed 0
ROGII_COMPETITION_ROOT=/tmp/rogii_synthetic/competition \
ROGII_REPORTS_DIR=reports/synthetic_validation \
python scripts/run_validation.py --n-splits 4 --spatial \
  --in-sample-diagnostic --label "SYNTHETIC PIPELINE VERIFICATION ONLY"
```

## Where the real results go

Real metrics are written to `reports/` (or `/kaggle/working/reports` on
Kaggle) by the same runner pointed at the real mount:

```bash
python scripts/run_validation.py --n-splits 5 --spatial
```

The two locations are kept strictly separate so a synthetic figure can never
be mistaken for a competition figure. The `--label` flag stamps the banner at
the top of every generated report; runs against the real mount carry no such
banner.
