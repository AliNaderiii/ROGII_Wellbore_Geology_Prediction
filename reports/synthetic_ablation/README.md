# ⚠️ SYNTHETIC HARNESS VERIFICATION ONLY

**Nothing in this directory is a competition result.**

Every file here was produced from the synthetic field generated by
`scripts/make_synthetic_field.py` (40 wells, seed 0), not from the ROGII
Kaggle data. The mount was not available in the environment where the
alignment/spatial ablation runner and the dip-alignment diagnostics were
written, so the synthetic field was used to prove they execute correctly end
to end.

## What these files do and do not establish

**They do establish:**

- `scripts/run_feature_ablation.py` runs all four branches (A/B/C/D) under both
  protocols to completion, cross-fitted by well ID.
- Every branch scores the identical well set within a protocol, so the deltas
  are paired.
- The spatial donor guard fires for branches C and D, and no spatial prior is
  built when no branch needs one.
- `scripts/diagnose_dip_alignment.py` computes all ten numbered diagnostics
  without reading a hidden TVT value into any feature.
- The keep/remove verdict logic fires and reports a decision.

**They do not establish anything about accuracy on the real data.** In
particular, the synthetic generator constructs `TVT = surface − Z` by
definition, which is exactly the geometric relationship the dip-constrained
model assumes — so the synthetic field cannot reproduce the real failure and
systematically flatters every geometry-based model. Only 40 wells were
generated, versus 770 eligible real validation wells.

**Do not quote any number in this directory as a validation result.**



## Filename convention (added in the real-run preparation)

Report filenames now follow the **evidence**, not the caller's intent:

- `real_*` is emitted **only** when the discovered well counts match the
  audited real mount exactly (773 train wells, 770 eligible).
- Everything else — synthetic, partial, subset — is emitted as `synthetic_*`
  and carries the `SYNTHETIC — NOT A COMPETITION RESULT` banner.

That is why this directory contains `synthetic_alignment_ablation_summary.md`
rather than `real_alignment_ablation_summary.md`. A file named `real_*`
anywhere in this repository is therefore always a real competition result, and
`src.real_ablation_reporting.is_real_run` is the single place that decides.

The A/B/C/D ablation has **not** been run against the real mount; no `real_*`
report exists yet.
